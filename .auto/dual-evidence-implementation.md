## Mechanics and trust boundary

The worker imports `span_retrieval_contract` directly. Its prompt, inventory, projection, native schema, strict validation, exact original-object restoration, and unavailable report are unchanged. The ordinary NLI child uses the production `package-child.mjs`, submit extension, native schema and original user including final_verification. Tests compare both ordinary child packets, including its repair, to a separate baseline SDK run. The parent system, source user and assembler remain baseline.

The borrowed dual-role SDK runs child then reviewer sequentially. Child creates exclusive 0600 private settings once. Reviewer checks their exact bytes read-only, with its own plugin, workspace and symbol; its registry, hook and session are cleaned up. Neither helper inherits parent conversation or the other helper's answer. The source reviewer gets all original factual fields in original order with only the top-level final_verification removed. Shared 8B weights do not establish statistical independence.

The bridge strictly parses raw JSON and validates with the assembler or imported retrieval contract before Pi can coerce values. Each helper has two completions maximum, parent three. Reviewer has only select_source_spans. Root Transport remains unchanged; candidate-local guards recheck original user identity, role models, schemas and the trusted SDK system envelope before every HTTP request. Root's nonparent role inference is mapped to reviewer only for its exact retrieval tool. The parent report has exactly recommendation and source_evidence. A failed ordinary submission is explicit recommendation_unavailable; failed retrieval is not no selection. Accepted ordinary advice is audited separately, with a parent-label comparison, never used to force a final label or IDs.
