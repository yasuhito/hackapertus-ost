# 1回呼び出し構成の比較（2026-10-16 午後）

## 背景

新版（70B親 + 8B子、コミット 76a0e6e 以降）の実行記録 420 件を調べると、70B 親の最終回答は 8B 子の提案と 420 件すべてで一致していた。親の 2 回の呼び出し（資料を読んで「子を呼ぶ」と返す 1 回と、子の答えを写す 1 回）が全トークンの 63%、待ち時間の 65% を占めていたので、1 回の呼び出しで済む構成を実行系に追加して測った。

- **S**: 1 つのモデルが 1 回のネイティブツール呼び出し（submit のみ）で答える。子セッションなし。
- **R**: S と同じだが、入力の構造で振り分ける。冊子を読む Task A は 70B、参照文だけの Task B は 8B。

どちらも、根拠を 1 つも示せない非中立回答は却下して 1 回だけやり直し、それでも示せなければ既定の中立回答にする（コミット 8d5c7e6 で Task B にもこの規則を戻した。外していた間、70B は話題違いの主張を根拠なしで「矛盾」と答え、Task B の F1 が 0.693 まで落ちた）。

温度 0 だが、同じ入力でも実行ごとに数件の差が出る。以下は各 1 回の実測で、差が 0.03 程度なら偶然の範囲と見るべき。

## 判断

S と R はどちらも、3 つの問題集すべてで現行を上回る。Q の 3 問題集平均は S 0.895、R 0.905。差は偶然の範囲だが、R は退避が少なく、トークンが約 8% 少なく、Task B で 70B の「話題違いを矛盾と言う」傾向を避けられる。**R を本番構成にする。** 切り替えは `PIPELINE` 環境変数 1 つで、`S` や `C` に戻せる。

## 8B 単独について

8B だけの 1 回呼び出し（S、8B）は開発用60 で Task A F1 0.714、Task B 0.808〜0.883、トークン 8,455、時間 2.3 秒。現行と同等の精度を 1/3 のトークンで出すが、70B の文書問題の精度には届かない。テキスト JSON 出力にすると Task A F1 は 0.361 まで落ちるので、ツール呼び出し形式が必須。
