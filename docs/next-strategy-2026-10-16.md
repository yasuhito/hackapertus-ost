## 診断で確定した事実

対象: 公開済みの DEV60 と PUBLIC60（どちらも開発で使用済み）。Task A で正解根拠がある 39 問を決定論的に調べた（モデル呼び出しなし）。

| 事実 | 件数 |
|---|---:|
| 正解根拠のページを、モデルに渡していなかった | 14 / 39（36%） |
| 正解根拠が pypdf 抽出のどのページとも 90 以上で一致しない | 3 / 39 |
| 渡していなかった DEV の 7 問のうち、v5 が判断も誤った | 3 / 7 |

原因は `track_2a/src/document_selection.py` の `page_section`。節の目印 `im detail|en detail|in dettaglio` が目次ページ（物理 4, 6, 8, 10...）に誤反応し、各議案の要約ページ（In Kürze / En bref / In breve。データセットの reference_string はここから取られることが多い）が落ちる。議案の区間そのものを間違える例もある（56 ページ冊子で [4, 5, 56] だけを選択、など）。

v5 の送信文脈は平均 38k 文字（約 28k トークン）、冊子全文は平均 117k 文字。全文送信は効率の評価で不利なので、選択を直す方向。

分類誤りの内訳（DEV60 × 5、正解→予測）:
- Task A: 矛盾→含意 18、矛盾→中立 17、含意→矛盾 10、中立→含意 5
- Task B: 含意→矛盾 15 / 35、矛盾→中立 10 / 60

言語の同異は主因ではない（同言語と異言語で誤り率がほぼ同じ）。

昨晩の 3 つの架構（8B の事実・区間選択役を親に追加）は Q を上げたが、形式失敗を増やし根拠提示を改善しなかった。そのままの再試行はしない。

## 優先順位

1. **ページ選択の修正（決定論、最優先）。** 目次ページを解析して、議案ごとの「要約 [a..b] + 詳細 [c..次議案の前]」区間を構築する。目次がない・崩れた場合は各ページ先頭のランニングヘッダ（Erste Vorlage / Premier objet / Primo oggetto など）の序数で区間を決める。単一議案冊子は全文。現行の正規表現は廃止。
   - 検証はモデルなしで行う: 公開 3 セットの全 PDF で、区間が互いに素で冊子を覆うこと、一次と二次の区間が一致すること、正解根拠ページが選択に含まれる率（一致可能な 36/39 のうち 33 以上が目標）、文脈文字数が現行以下であること。
   - ルールは冊子の構造語彙だけで書く。個別の正解行に合わせた閾値調整はしない。閾値を動かすときは構造上の理由を記録する。
2. **根拠の決定論的な補完。** 評価器は短い方を長い方に整列するので、正解箇所を含むページ（5,000 文字以下）は確実に当たる。モデルが選んだ区間のページを先頭に置き、残りの枠を選択区間内の BM25 上位ページで 5 件まで埋める。5,000 文字超のページだけ区間単位に落とす。中立予測にも参照箇所を付けるかは所有者の判断。
3. **プロンプトの削減実験。** 矛盾→中立は `NEUTRAL_GUARD` の「同一命題の明示的否定が必要」が、数値・主体・年を入れ替えた矛盾を中立に押している疑い。Task B の含意→矛盾は `FINAL_VERIFICATION` の極性比較段落が疑わしい。まずモデルなしで claim と reference_string の差分種別（数値・否定・主体・条件・言い換え）を自動分類して誤り種別と突き合わせる。次に短縮 SYSTEM を DEV60 × 3 で比較し、(2→1) と (0→2) の移動方向だけで判定する。
4. **本番 CLI の契約整合（低リスク）。** `make run` は PIPELINE=C（70B 親 + 8B 子、ネイティブツール）を使うので測定と一致している。`run-local` 経路の `predict.py` は SYSTEM で submit ツールを指示しながらツールを宣言せず、テキスト JSON を要求している。提出前に一致させる。

## 検証順序

1. ページ選択を決定論的に検証（公開 3 セット、モデルなし）。
2. ページ選択のみ適用で DEV60 × 3。基準: Hit@5 上昇、F1A 非低下、形式失敗 0、トークン非増加。
3. 根拠補完を追加して DEV60 × 1（Hit@5 のみ確認）。
4. プロンプト削減を DEV60 × 3 で独立比較。
5. 採用構成を PUBLIC60 × 1 で二次確認。
6. 封印中の 60 問は最終候補と v5 の一度きりの比較に温存。事前登録の基準: F1A ≥ .60、F1B ≥ .75、Hit@5 ≥ v5 + .10、形式失敗 0、トークン ≤ v5。

## 前提とリスク

冊子の目次とランニングヘッダの構造が年度を通じて一貫していること（1 冊で確認済み、全 PDF での確認が必要）。古い冊子では pypdf の抽出が崩れる可能性があり、二次・三次のフォールバックで吸収する。

### 調べて見送ったこと

- 法律条文のページは文脈の 48% を占めるが、正解根拠の 11%（55 / 501）がそこにある。条文を落とすトークン削減は根拠と判断の両方を損なうので見送り。
